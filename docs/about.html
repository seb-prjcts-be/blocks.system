about

from a collection to a library

The starting point was a collection of standalone visual elements. The durable idea underneath it was simpler: every object should be usable, addressable and replaceable on its own.

the boundary

blocks.system manages fields, objects, registration and adapter lifecycles. It does not know what a wave, p5 sketch, web component, iframe or renderer is.

This boundary allows one local project to connect waves while another user fills the same blocks with plain HTML, canvas, video, controls or a runtime that does not exist yet.

the name

The name describes the object model without referring to windows or to one visual technology. The public namespace stays lowercase: system properties under blocks.system, object properties under block.

the development system

The repository mirrors the proven p5.waves documentation and release structure: a live showcase, standalone examples, a guide, a complete API page, bilingual READMEs, generated manifest, source/min parity checks, tests and GitHub Pages deployment.

The sites use black as the regular block colour. A few blocks may use pure red, green, blue, cyan, magenta or yellow as exceptions. This is a site convention, not a core API rule.

The structure is shared; the libraries are not coupled. blocks.system has zero runtime dependencies.
