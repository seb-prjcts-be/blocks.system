failures + boundaries

fail early Invalid input throws.

Expect errors for invalid or duplicate ids, missing fields, impossible grid positions, overlaps, unknown definitions, incomplete adapters and colorVariation without colors. Catch only errors your interface can recover from.

definitions + adapters

Definitions describe reusable content. Register definitions and their lifecycle adapters on the shared system.

const definition = {
  id: "block-note",
  adapter: "note",
  label: "note",
  medium: "html",
  category: "text",
  description: "a small note",
  defaults: { text: "hello" },
  attributes: [],
  requires: []

field events + DOM hooks

The field dispatches blocks:reorder after pointer or keyboard reordering and blocks:change after explicit state changes.

field.addEventListener("blocks:reorder", (event) => {
  const {
    id, input, mode, key,
    fromIndex, toIndex, from, to, direction
  } = event.detail;
});

field.addEventListener("blocks:change", (event) => {
  const { type, id, ids } = event.detail;
});
hookpurpose
.blocks-system-surfaceThe attached field and its layout tokens.
.blocks-system-objectOne outer block.
.blocks-system-menuStructural title bar and pointer drag area.
.blocks-system-titleKeyboard drag handle with button semantics while dragging is enabled.
.blocks-system-contentContent host.
.blocks-system-drop-previewPointer landing preview.
[data-block-object]Stable block id.
[data-block-variant]Resolved appearance. Custom variant names pass validation and land here for consumer styling — for example a light footnote weight.
[data-block-color]Color selected from the user's array.
[data-block-minimized]Minimized state.
[data-draggable]Surface drag state.

For blocks:reorder, input is pointer or keyboard, mode is grid or flow, and positions are { column, row } or null. For blocks:change, type is compact, minimize, restore or remove; id is one block or null, and ids lists affected blocks.
