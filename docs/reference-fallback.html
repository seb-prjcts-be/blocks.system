create the system

Import the factory and create one independent blocks system. The module also exports a shared system when one global instance is enough.

import { createBlocksSystem } from "./blocks.system.mjs";

const blocks = createBlocksSystem({
  catalogUrl: null,
  random: Math.random,
  snap: false,
  placement: "fixed",
  draggable: true,
  resizable: false,
  font: null,
  labels: {},
  variant: "random",
  colorArray: [],
  colorVariation: 0,
  inversionVariation: 1 / 3,
  blockDefaults: { menu: { minimize: true, close: true } },
  blocks: []
});

set the grid

Define the field dimensions before placing blocks. Fixed placement keeps explicit addresses; flow placement uses DOM order and needs only each block's starting size.

blocks.placement = "flow";
blocks.setGrid(4, 4);

create a block

add() turns content into one block and returns its controller. id identifies the block; title is optional visible text in its titlebar.

const block = blocks.add(content, {
  id: "hello",
  title: "hello",
  menu: { minimize: true, close: true },
  variant: "regular",
  minimized: false,
  draggable: true,
  resizable: true
});

size and position

Set a block span in whole grid units. Fixed placement may add coordinates; flow placement follows DOM order and automatically shifts later blocks.

block.span(4, 2);
block.place(1, 1);

const layout = blocks.exportLayout();
blocks.restoreLayout(layout);
kind + contractreturnspurpose

method · place(column, row)blockSet one-based grid coordinates.

In flow placement, add blocks in the desired initial order—for example after sorting titles by name—and call span() without place().

dragging and order

draggable enables pointer and keyboard movement. Fixed placement moves grid coordinates; flow placement changes DOM order. Optional resize lines change a flow block's span.

field.addEventListener("blocks:reorder", (event) => {
  const {
    id, input, mode, key,
    fromIndex, toIndex, from, to, direction
  } = event.detail;
});

definitions + adapters

Definitions describe reusable content. Register definitions and their lifecycle adapters on the shared system.

const definition = {
  id: "block-note",
  adapter: "note",
  url: "./notes.html",
  markup: "<p>hello</p>",
  label: "note",
  medium: "html",
  category: "text",
  description: "a small note",
  defaults: { text: "hello" },
  attributes: [],
  requires: []
};

blocks.register(definition, { replace: false });
blocks.registerAdapter("note", adapter, { replace: false });

const notes = blocks.list({
  query: "note",
  adapter: "note",
  medium: "html",
  category: "text"
});

adapter lifecycle methods

Adapters own mount and cleanup lifecycle; the system methods below use those lifecycle hooks for registered definitions.

await blocks.mount("block-note", target, { text: "hello" });
await blocks.remount("block-note", target, { text: "updated" });
const source = blocks.snippet("block-note", { text: "hello" });

failures + boundaries

fail early Invalid input throws.

Expect errors for invalid or duplicate ids, missing fields, impossible grid positions, overlaps, unknown definitions, incomplete adapters and colorVariation without colors. Catch only errors your interface can recover from.
