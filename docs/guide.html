guide

build with blocks

Start with a field, add ordinary DOM content, then introduce adapters only where another runtime needs a lifecycle.

1. install

Load the layout stylesheet and import the native ESM module. The named export and window.blocks.system point to the same singleton.

<link rel="stylesheet" href="./blocks.system.css">

<script type="module">
  import { system } from "./blocks.system.mjs";
</script>

2. attach a field

The system never claims the entire page. Give it one explicit selector or DOM element.

<div id="field"></div>

<script type="module">
  import { system } from "./blocks.system.mjs";
  blocks.system.attach("#field");
</script>

attach() fails early when the target does not exist. This keeps integration mistakes visible.

3. define the grid

setGrid(x, y) means columns and rows. Snapping and dragging can be changed at runtime.

blocks.system.setGrid(4, 2);
blocks.system.snap = true;
blocks.system.draggable = true;

Drag a block by its menu bar. The stylesheet supplies the agreed composition by default: 6px intervals, black blocks, warm paper, a 22px menu and 7px content inset. Override its CSS variables only when your own composition deliberately differs.

smart variants

New blocks choose a stable random monochrome variant: regular is twice as likely as inverse. The pure red, green, blue, cyan, magenta and yellow variants are built in but stay explicit. On mouseover, the original thicker inset line appears without moving the layout.

blocks.system.variant = "random";

const automatic = blocks.system.add(content);
const inverse = blocks.system.add(content, { variant: "inverse" });
automatic.variant = "blue";

optional font

The CSS defaults to Oswald with a system fallback. Loading an external font stays an explicit choice:

blocks.system.font = {
  href: "https://fonts.googleapis.com/css2?family=Oswald:wght@400;600&display=swap",
  family: "Oswald"
};

4. add content

A block accepts a trusted HTML string, a DOM node, or a factory function returning either form.

const html = blocks.system.add("<p>hello</p>");

const canvas = document.createElement("canvas");
const drawing = blocks.system.add(canvas);

const lazy = blocks.system.add(function () {
  const node = document.createElement("button");
  node.textContent = "native control";
  return node;
});

HTML strings are interpreted as markup. Never pass untrusted user input; build a DOM node and assign textContent instead.

5. configure one object

add() returns the controller for that object. A menu, minimized state, span, grid position, variant and colour belong to the object, not to the system.

const block = blocks.system.add(content, { id: "preview" });
block.menu("preview", { close: true, minimize: true });
block.color = "#ef3e36";
block.span(2, 1);
block.place(3, 2);

// later
block.remove();

minimize and restore

Every menu is minimizable by default. A minimized block shows only its header but keeps its configured span and position reserved, so restoring can never collide with another block. Set minimize: false only when a menu must not expose that control.

block.minimized = true;
block.minimized = false;

Content centers while it fits and scrolls inside the block when it overflows. The base stylesheet defines only states; motion remains a separate optional layer.

6. connect a runtime

Use an adapter when content needs mounting, cleanup, readiness or a reusable snippet. The runtime remains outside the core.

  1. register an adapter

    Give it a lowercase kebab-case id and a mount() function.

  2. register a definition

    Describe the object and its default settings.

  3. mount into a host

    The adapter returns the root element it placed inside the host.

blocks.system.registerAdapter("counter", {
  mount({ host, settings }) {
    const node = document.createElement("button");
    let value = settings.start;
    node.textContent = value;
    node.addEventListener("click", function () {
      value += 1;
      node.textContent = value;
    });
    host.appendChild(node);
    return node;
  }
});

blocks.system.register({
  id: "click-counter",
  label: "click counter",
  adapter: "counter",
  medium: "html",
  defaults: { start: 0 }
});

await blocks.system.mount("click-counter", "#host");

how to extend the project

Keep the core small. Put reusable demonstrations in examples/name/, API explanation in the two READMEs and docs, and lifecycle integrations in separate adapter packages or project-local files.

An API change is complete only when source, minified source, tests, examples, English README, Dutch README, guide, API reference and manifest agree.
