# blocks.system v0.5.0

`v0.5.0` makes the library the owner of its rows, lets minimal code produce a
usable standard block, and settles the contracts that were still ambiguous.
It was shaped by the first real consumer, the Lucas Gent site, whose generic
workarounds moved into the library.

## Breaking changes

- `setGrid(columns, rows)` now fixes the columns and sets the **minimum** rows.
  The real row count follows the content: spans, places, drops, keyboard
  moves, minimizing, docking and `hidden` grow and shrink it, and `blocks.rows`
  always reports the current count. Rows are never "too small" any more; only a
  block wider than the grid throws, with `error.code === "BLOCKS_GRID_TOO_SMALL"`.
- The default `variant` is `regular`. Pass `variant: "random"` to keep the
  chance-driven appearance; `colorVariation` and `inversionVariation` only act
  on random blocks.
- `block.menu(name, options)` means the same as `add()`: `true` or nothing is
  the inherited default menu, `false` a titlebar without controls, and an
  object fills its missing options from `blockDefaults.menu`. The old boolean
  shorthand for `close` is gone.
- A minimized block releases its extra rows in fixed-grid as well as flow-grid.
  Restoring it, or undocking it, onto a place taken meanwhile releases the fixed
  address so the block flows to the next free cell instead of overlapping.
- The destructive remove control shows `⊗`; `×` belongs to the reversible
  close-to-dock action alone. Undocking announces its own `undock` label;
  `restore` belongs to minimize.
- A short block in the free layout keeps a minimum width
  (`--blocks-block-min-width`, 180px).

## Added

- `rowHeight` (option and property): fixed row tracks in pixels, so the field
  grows and shrinks with its rows and the page no longer owns the height.
- Zero-config use: `add()` without `attach()` creates its own field at the end
  of the body, `startBlock(content, options?)` adds to the shared system, and
  `span` and `place` travel with `add()`.
- `restoreLayout(layout, { grid })` switches the grid and the saved spans in one
  atomic step, for example at a responsive breakpoint.
- The native `hidden` attribute removes a block from the grid; measuring and
  dragging leave it untouched until it returns.
- `blocks:change` now reports `dock`, `undock`, `layout` (one block's span,
  place or measured height) and `grid` (columns or rows), so every field that
  `exportLayout()` records has an event.
- The dock rail reserves its own space above the grid instead of covering the
  first block.

## Fixed

- `block.dock()` without an argument docks instead of undocking.
- Undocking no longer lands on a cell another block took meanwhile.
- `menu: false` no longer announces a block as draggable when it has no
  titlebar to drag.
- The resize outline appears while a flow-grid block is being resized.
- The TypeScript declarations list every `blocks:change` type and the
  `dock`/`undock` labels.

## Migration

1. Treat the second `setGrid()` argument as a minimum. Remove any code that
   grows a measurement grid and catches "too small" errors for rows; keep the
   `BLOCKS_GRID_TOO_SMALL` check only for columns.
2. Let the library size the field: pass `rowHeight` in pixels and drop custom
   row counting or field-height code. Keep the default when the page should
   own the height through `1fr` rows.
3. Add `variant: "random"` where the chance settings should keep drawing
   appearances.
4. Replace `block.menu(name, true|false)` in its old close-shorthand meaning by
   an explicit `{ close: true }` object.
5. Listen for the `layout` and `grid` change types when persisting layouts.

This project remains `private: true`: distribution is the GitHub release tag
and its jsDelivr ESM/CSS URLs, not npm.
