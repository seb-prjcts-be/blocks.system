# blocks.system v0.6.1

`v0.6.1` gives `reset()` a target the application can set. In `v0.6.0`,
`reset()` returned every block to its state at `add()`. That is too early for
an application that sets spans, order and a personal override afterwards: the
Lucas Gent site got 1×1 spans and, after a reload, the visitor's own order
back instead of the editorial layout.

No documented contract breaks. Layout snapshots stay `version: 1`.

## Added

- `blocks.saveBaseline()`: the current order, spans, places, minimized,
  docked and pinned state become the target of `reset()`. Blocks added later
  join the baseline at the end. Without the call, `reset()` keeps returning to
  the `add()` state, so existing consumers are unaffected.

## Migration

1. Nothing is required.
2. If the application applies its own layout after `add()`, call
   `blocks.saveBaseline()` once that layout is complete and before restoring a
   personal override; `reset()` then returns to that layout.

This project remains `private: true`: distribution is the GitHub release tag
and its jsDelivr ESM/CSS URLs, not npm.
