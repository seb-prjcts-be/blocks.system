# blocks.system v0.6.0

`v0.6.0` lets visitors shape a page for themselves: favorites that stay in
front, a dock rail that can sit below the grid and show a summary, and one
`reset()` that returns everything to the editorial order. Every block is in
exactly one of three states: regular, favorite or docked. The design was
settled with the Lucas Gent site as the first consumer; the library holds the
generic part, the site keeps its own buttons and browser storage.

No documented contract breaks. Layout snapshots gain a `pinned` field and stay
`version: 1`, so saved layouts from `v0.5.0` restore unchanged.

## Added

- `block.pin(value?)` and `block.pinned`, with the opt-in menu option `pin`
  (☆ / ★). A pinned block moves in front of the unpinned blocks, in the order
  it was pinned; unpinning drops it to the front of the unpinned group.
  `exportLayout()` reports `pinned`, `restoreLayout()` applies it, and
  `blocks:change` publishes `pin` and `unpin`. Labels: `pin`, `unpin`.
- A favorite stays visible: `dock()` on a pinned block does nothing and its
  dock button is disabled with the `pinnedStaysVisible` label; a docked block
  ignores `pin()` and hides its star. A refused action publishes no change.
- `dockPosition` (option and property): `"top"` keeps the rail above the grid,
  `"bottom"` moves it below the last block, and the field reserves space on
  that side (`data-blocks-dock-position`).
- `add(content, { summary })` and `block.summary(content | null)`: short
  content the docked chip shows instead of the title alone
  (`.blocks-system-summary`, `data-block-summary`).
- `blocks.reset()`: every block returns to its `add()` order, span, place and
  initial minimized state, undocked and unpinned, and one `blocks:change` of
  type `reset` names every block in `ids`.
- The docked chip offers ↩ to return, instead of `+`.

## Fixed

- `restoreLayout()` cleared a live pin only after reordering, so a favorite
  could overrule the saved order. Dock and pin now go off before the saved
  order is applied and come back in that order.

## Migration

1. Nothing is required. Saved layouts keep `version: 1`.
2. To offer favorites, enable `menu: { pin: true }` and persist `pinned` from
   `exportLayout()` alongside the order; listen for `pin`, `unpin` and
   `reset`.
3. To move the rail below the grid, pass `dockPosition: "bottom"` and give
   blocks a `summary` where a title alone says too little.
4. A "reset everything" button calls `blocks.reset()` and clears the
   consumer's own storage.

This project remains `private: true`: distribution is the GitHub release tag
and its jsDelivr ESM/CSS URLs, not npm.
