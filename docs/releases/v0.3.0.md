# blocks.system v0.3.0

`v0.3.0` aligns the runtime, TypeScript declarations, manual, API reference,
examples and immutable CDN snippets on one release.

## Breaking changes

- Removed the `margin` system option/property and the library-owned
  `--blocks-margin` surface padding. Consumer CSS now owns spacing around and
  inside a field.
- A fresh system now includes the built-in `html` adapter, so
  `listAdapters()` starts with `"html"` instead of an empty array.
- Replacing that built-in adapter requires
  `registerAdapter("html", adapter, { replace: true })`.
- `definition.url` is now meaningful address metadata. `address(id)` prefers
  it over the system catalog URL and preserves consumer query values.

## Added

- `BlockDefinition.url` and trusted `BlockDefinition.markup`.
- `block.describe({ url })` for serialising a live block into a definition for
  the built-in `html` adapter.
- Runtime/types/reference drift checks and an immutable-tag check for the CDN
  installation snippets.

## Fixed

- Removing the last block from a fully occupied grid row releases that whole
  row for later layout, including multi-column spans.
- Documentation now distinguishes current source from stable distribution and
  keeps explanation/code blocks protected, resettable and readable.

## Migration

1. Move former `margin` values to consumer CSS, for example padding on the
   attached `.blocks-system-surface`.
2. If registering an adapter named `html`, either choose another id or pass
   `{ replace: true }` deliberately.
3. Treat definition URLs as addresses; do not store unrelated free metadata in
   `definition.url`.

This project remains `private: true`: distribution is the GitHub release tag
and its jsDelivr ESM/CSS URLs, not npm.
